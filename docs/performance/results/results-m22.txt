# Milestone 22 (trading days), measured on the office Ubuntu machine (i3-7100, 2 cores / 4 threads,
# SATA SSD) on 2026-10-05, release builds, in the stock-rust container, journals on a Docker volume.
# new = this milestone's binary; m21 = the milestone 21 binary (commit a4860c7), which has no days.
# Same order volume: new-5-days is 5 days of 200,000 orders; m21-1m is 1,000,000 orders in one go.
# Every run had a warm replica beside it (the snapshot writer, every 10,000 commands, and since
# milestone 22 also right after each open), started as soon as the journal appeared. "warm ...
# not yet serving" means it was still in its first catch-up when the benchmark finished (it binds
# /status only once caught up); the time it then needed to catch up is the lag. Restarts start the
# primary on the run's files and time it until "recovered through"; the first loads the warm
# replica's last snapshot, the second the snapshot the first restart wrote at startup.
# Scripts: m22-measure.sh, then m22-followup.sh on the same journals.
